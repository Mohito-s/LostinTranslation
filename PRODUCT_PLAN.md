## 1. Тезис: почему уходим от «обогащения промтов»

Текущая идея — лингвистический middleware: наш AI-слой находит «культурные потери»
и вставляет контекстный блок в промт до отправки в целевую LLM (`/api/enhance`).

Риск: LLM быстро учатся понимать культурные нюансы сами
(«行けたら行く», «да, но нет», `Jein`). Уже через 1–2 года прямая инъекция контекста
станет commodity-функцией моделей, и за «прослойку» перестанут платить.

**Что остаётся ценным независимо от прогресса моделей:**
1. **Контроль качества** — проверка перевода/локализации на потери смысла (QA).
2. **Данные** — курируемая база «лингвистических мин» и бенчмарк по моделям.
3. **Вертикальные инструменты** — линтеры, плагины, SDK для i18n-пайплайнов.

Направляем проект с «pressure-инъекции» (injection) на «измерение» (evaluation).

## 3. Три направления

### A. Культурный QA переводов (главный кандидат)
**Что это:** пользователь отправляет пару «исходник → перевод», мы возвращаем отчёт:
какой смысл потерян, тон, вежливость, register, категория риска (severity), альтернативы.

**Кому:** продакты локализации, гейм-студии, SaaS с i18n, команды поддержки чат-ботов.

**Почему не умирает:** QA нужно всегда — модели меняются, а «правильно ли передано
намерение» проверять придётся постоянно.

**Что сделать нового в коде:** режим сравнения (второй текст в `/api/analyze`,
diff по потерям), северити-шкала, экспорт отчёта (MD/PDF), SDK.

### B. Открытый датасет + бенчмарк
**Что это:** публичная база «минимальных пар» (фраза → что реально имеет в виду носитель)
+ регулярный ранкинг LLM: какая модель как справляется. В духе лингвистического GLUE.

**Кому:** исследователи, продуктовые команды, LLM-провайдеры (им это самим выгодно).

**Почему ценно:** оценка моделей не стареет; графика «gemini проиграла на 行けたら行く
в 2026, но справилась в 2027» — вечный маркетинг и контент.

**Что сделать:** нормализовать примеры в единый JSON (CC-BY), страница-бенчмарк,
автотест против реальных моделей по расписанию.

### C. I18n-линтер для CI
**Что это:** GitHub Action / CLI-плагин: при релизе локализации сквозь пайплайн
проверяет строки на культурные мины (идиомы, недопустимые частицы, потерянная вежливость).

**Кому:** команды, которые шлют полу-переводы без ревью локальщика.

**Что сделать:** CLI + GitHub Action + PostgreSQL-хранилище правил, интеграция в код-ревью.

## 4. Рынок (кратко, без фантазий)

- Рынок локализации — десятки миллиардов $/год; большой процент компаний уже
  локализует ИИ-контент и нуждается в контроле качества.
- Существующие платформы (Phrase, Lokalise и др.) дают **ручной** QA (чек-листы,
  ворфлоу ревьюеров), но почти никто не даёт **автоматический культурный анализ**.
- Ниша «культурный слой» — почти пустая. Рынок настоящий, но требует точного
  позиционирования и демонстрируемой точности.

## 5. Юнит-экономика (навскидку, уточняется потом)

Стоимость вызовов Gemini (flash) — порядка 1–2 центов за один анализ.
**Важно:** все ключевые демо-примеры обслуживаются локально (mock-режим) — витрина
и датасет фактически бесплатны. Платная себестоимость начинается только на
«произвольном» тексте реальных пользователей.

Модель (freemium B2B):
- **Free:** ~10 анализов/мес произвольного текста + открытый датасет. Цель — воронка.
- **Pro:** $49–99/мес: безлимит, отчёты, SDK, история и бенчмарк-доступ.
- **Enterprise:** кастом + SLA + on-prem.

Ориентиры: конверсия free→paid 2–3%; 1000 free → 20–30 paid → ~$1.5–3k MRR
на пороге «интересного бизнеса». Себестоимость для 30 paid — сотни $
(это не проблема).

Лицензия: **AGPL-3.0 для ядра** (открыто, привлекает контрибьюторов), платная
ценность = хостинг + SDK + управляемые датасеты + SLA (классическая модель для
AGPL-проектов). Двойное лицензирование — отдельным решением, если захотим
коммерческое ядро.

## 6. Open source — роль и сценарий

- Репозиторий должен выглядеть как «настоящий» проект: README EN, демо-гифки,
  Release v1.0, бейджи CI, лейбл «open dataset».
- Датасет — отдельный репозиторий/пакет (`lost-in-translation-data`), это
  приглашает сообщество добавлять языки и примеры (наш скилл `lit-new-language`
  уже описывает процесс).
- Бенчмарк-страница — магнитом для stars и прессы.
- Контрибьюторам — берём на себя задачи «good first issue» по датасету.

## 8. Риски и метрики

**Риски**
- Модели сами станут хорошим QA → парируем: точность на датасете, человек-центричность,
  интеграции (линтер/SDK) удерживают вертикаль.
- Низкая готовность платить → метрика-флаг: бесплатно открытая точность, плати за
  интеграцию и надёжность.
- Датасет «не народный» → мульти-язычность и инфраструктура бенчмарка как контент.

**Метрики**
MRR, free→paid, размер датасета (примеров/языков), деплоев линтера, позиция
бенчмарка, звёзды/форки репо.
